2. WHAT THIS PHASE INCLUDES (THE FEATURES, AS A USER SEES THEM)
--------------------------------------------------------------------------------
App lock (Settings > Security and backup)
- A PIN of 4 to 12 digits, asked when EchoMind opens, after idle time (1 minute to 1 hour,
  or never), when Windows locks, and before the computer sleeps. "Lock now" too.
- While locked, nothing can be read: the main process refuses all data, recordings cannot
  play, and notifications say "unlock to see" instead of naming recordings or tasks.
  A recording in progress keeps recording.
- Wrong PINs: 5 free tries, then waits of 30 seconds doubling to 15 minutes, which survive
  a restart.

Backup and restore (Settings > Backup and restore)
- One encrypted file with every recording, transcript, summary, document, chat, Studio
  result, task and setting, saved wherever you choose (USB drive, another disk, or a
  folder your cloud drive syncs). Progress shown; the last backup date is remembered.
- Restoring checks the password at once, checks the whole file for damage or tampering,
  and puts the library in place when EchoMind restarts. The replaced library is kept until
  you remove it. API keys are never in backups.

Share bundles
- More > Share as a bundle on any recording: one ".echomind" file with the audio,
  transcript and speaker names, summaries, chapters, documents, tags and bookmarks.
- Import it from Home > Import, or double-click it once EchoMind is installed.

Start with Windows
- Opens EchoMind minimized when you sign in, so task reminders appear on time.

The installer
- EchoMind-Setup-0.1.0.exe: per-user (no administrator rights), choice of folder, Start
  menu and desktop shortcuts, the EchoMind icon, the .echomind file association, and the
  FFmpeg add-on. Uninstalling keeps your library.


3. KEY DECISIONS
--------------------------------------------------------------------------------
D1  The lock is enforced in the main process, not drawn over the screens: a locked app
    answers only "unlock" (and keeps an ongoing recording safe).
D2  PIN only. Windows Hello is not available to Electron apps, so it is not offered.
D3  App lock is not disk encryption, and the app says so. BitLocker is the right tool for
    files at rest; EchoMind's job is to keep its own window and data API closed.
D4  One archive format for backups (encrypted) and bundles (plain): streamed, so libraries
    of many gigabytes never sit in memory, with names and sizes checked on the way in.
D5  AES-256-GCM with scrypt (N=2^16) and a fresh salt and IV per backup; a small encrypted
    check catches a wrong password before the whole file is read.
D6  Restores swap at the next launch, before the database opens, so old and new data can
    never mix, and the previous library is kept aside.
D7  Bundle audio goes through the normal import pipeline, so a shared file is checked like
    any other, and every manifest field is validated and limited.
D8  "Start with Windows" registers only from the installed app, so development builds never
    add themselves to startup.


4. FIXES AND IMPROVEMENTS MADE WHILE BUILDING AND REVIEWING
--------------------------------------------------------------------------------
F1  [Accessibility] The audit found three WCAG AA colour-contrast failures: amber warning
    text (4.2:1), white text on the dark-theme record button, and the dimmed hint on Home's
    primary action. Fixed at the design-token level; every main screen now passes in both
    themes.
F2  [Privacy] A recovery error could log a file path. All main-process logging now goes
    through one helper that removes paths and key-like strings. Tested.
F3  [Layout] The lock wrapper briefly broke the shell's full-height layout (seen in a
    screenshot); fixed with a box-less wrapper.
F4  [Bug] A size check in bundle import was written with the wrong operator precedence and
    would not have limited anything. Caught in review and fixed.
